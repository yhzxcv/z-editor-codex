## 三层结构

```
js/level/    关卡逻辑层 —— 从 Kotlin 移植，纯函数，不碰 DOM
js/editor/   编辑器界面层
data/        数据：模块注册表、对象骨架、模板、图鉴条目
vendor/      预打包的 CodeMirror 6（见「构建」一节）
```

**逻辑层和界面层是分开的**，这不是洁癖：逻辑层全部是不碰 DOM 的纯函数，
所以 `tools/check-level.js` 里那 211 条断言能在 Node 里直接跑，不用开浏览器。
写界面时踩的坑基本都靠这个分工在提交前拦住了。

侧栏现在有**三个平行页签：对象 / 模块 / 图鉴**。原先的「校验」页撤了 —— 它五张卡片里
有三张跟对象树原样重复，而且重复的那份不能点、不能跳文本；「插入」页拆成「模块」和
「图鉴」两个，因为图鉴是个 2333 条、五个类别的数据集，埋在模块按钮下面当第三段是找不到的。

### 术语规范

**用词以这里为准。** 新写的代码、注释、断言标签、文档都照这张表，别再引入同义词 ——
同一个概念有两种叫法时，读代码的人会以为它们在说两件不同的事。

| 用 | 不用 | 指什么 | 判定在哪 |
|---|---|---|---|
| **孤立模块** | ~~孤儿~~、~~孤立对象~~ | 没有任何对象引用到它，因而不**可达**的对象 | `Parse.findOrphanedObjects` ← `computeReachableObjects` |
| **失效引用** | ~~悬空引用~~、~~悬空的 RTID 引用~~、~~失效的模块引用~~ | 落空的 RTID，两档都算：写的是**本文件里**的对象却找不到（`missing`），或参考文件里**没有**这个别名（`alias-typo`）。`Modules` 数组、每一波、对象深处，全算 | 三个判定取并集再去重，见下 |
| **参考文件里没有** | ~~灰字提示~~（当名词用时） | **界面文案，不是另一个概念** —— 指 `kind === 'alias-typo'` 那一档（`classifyRef` 判成 `external-typo`）。可能拼错了，也可能快照比游戏旧，但两者都算失效引用 | `Report.build` 分出的 `kind`；对象树那一行的 `title`（2026-09-22 起不再写进行内 —— 见下） |
| **支撑对象** | | 被引用、但既不是模块也不是波次的对象（僵尸类型、属性表……），所以删不得 | `Outline` 结果的 `supporting` |

外部来源我们**没有**数据时（`external-unknown`，如 `@SkillTypes` 2938 条）一律**不判** ——
上游 `ReferenceRepository` 就是这么设计的 fail-open，见「保真」一节。

「孤立模块」是**界面和代码共用的词**，用户看得见的地方一律这么写：状态栏的
「N 个孤立模块」（`main.js`）、汇总条的「N 个孤立模块」、对象树的段落标题和
「清理这 N 个孤立模块」按钮（`tree.js`）。这条是**踩过坑才统一的** ——
原先同一个概念在三处分别叫「未引用」「未被引用的对象」「孤立模块」，
读的人很容易以为是三种不同的东西。

⚠ **英文标识符没跟着改**，仍是 `orphan` / `orphaned` / `findOrphanedObjects`。
一是它对应上游 Kotlin 的同一个概念，改了丢掉这层对应；二是 `reference/*.js` 是上游
资产的原样快照，里面本来就有 `Orphaned` 字样，逐字节不能动。所以规矩是
**中文一律「孤立模块」，英文一律 `orphan`**，两边都不许再冒出第三种写法。

#### `失效` 和 `悬空` 是怎么收口的

原先同一个东西换文件就换叫法：`Outline` 的 `dangling` 在对象树上叫「失效引用」、
在校验页叫「悬空的 RTID 引用」；`findInvalidLevelModuleReferences` 在校验页叫
「失效的模块引用」、在 `parse.js` 的注释里却写「悬空引用」。**但它们不是同一个集合，
两个方向都不互相包含** —— 这才是真正的问题，光统一叫法会掩盖它：

| 出问题的引用在哪 | `missing`（本文件里找不到） | 参考文件里没有这个别名 |
|---|---|---|
| `LevelDefinition.Modules` 里 | `invalid` 和 `dangling` **都报** | 只有 `invalid` 报 |
| 某一波的数组里 | 只有 `dangling` 报 | 只有 `notes` 收着 |
| 对象深处（objdata 里） | 只有 `dangling` 报 | 只有 `notes` 收着 |

- `invalid`（`findInvalidLevelModuleReferences`）**窄而深**：只走 `Modules` 一个数组，
  但 `missing` / typo 两种都管 —— 照抄 Kotlin 的窄口径。
- `dangling`（`Outline` 的）**宽而浅**：走 `Modules` + 每一波 + 每个对象的 `objdata`
  三个地方，只管 `missing`。
- `notes`（`Outline` 的）同样**宽而浅**、同样这三个地方，只管 typo。

左上角那格**两边都报**，所以原先 `panels.js` 把两者直接相加当计数时，同一件事被数了两遍。

现在的收口是：**判定层各留各的语义，展示层合成一处**（`js/level/report.js`）。

- `Report.build` 取**并集**，按**整串 RTID** 去重，同一条的多个出处合并成 `wheres`
  —— 「这个引用在 Modules 和第 2 波都烂了」是 **1 条、两处出处**，跟用户的直觉一致。
- `kind` 取 `missing`：它的结论更硬（本文件里就是没有），`alias-typo` 还留着
  「说不定参考数据旧了」的余地。
- **三格全在红档**。第一格是因为「原则上不能出现落空的模块」：`Modules` 是游戏真正
  读来加载模块的地方，`RTID(x@LevelModules)` 而注册表里没有 `x` 按上游就是错误。
- **第二、三格的 typo 也进来了**（原先只有它们走灰字 `notes`，明确写着"不算错误"）。
  用户后来的要求是「参考文件没有的也划为失效引用」：一处引用了参考数据里不存在的
  别名，游戏加载时同样会落空，不该缩在另一段里当提示。**已知代价**：参考快照比游戏
  旧时，那些新增的别名会一起报红 —— 该更新的是 `reference/` 下的数据，不是这个判断。
- 顺带两个渲染面也归一了：树上**不再有**「参考文件里没有」那一段（并进失效引用），
  节点上的灰点也不再有 —— 两档共用一个 ⚠，分档写在悬停提示里。
  2026-09-22 又收了一轮（用户：「侧边栏失效引用直接红字写失效代号…这些引用落空了：
  这一段灰色字以及后面参考文件没有这些提示去掉」）：**行里那个词和段落底下那段灰字
  说明都没了**，现在一行只有两样东西 —— 失效的那个代号（红字）和它出现在哪儿；
  两档的区分退进行上那个代号的 `title`。理由：用户在这一段要找的是"哪个名字坏了"，
  扫一列代号的时候，中间插一个词、底下压一段说明，全是噪音。
- 边界（**别顺手扩大**）：`classifyRef` / `resolveList` 的语义一个字没改。
  `external-unknown`（我们**没有**数据的来源）继续不判 —— 那不是「外部源没有这个
  别名」，是「我们没这个源」，硬判就是满屏误报。

对象图里任意位置的 ⚠ 走的是**节点级**的 `nodeOf(...).dangling`（`tree.js` 的悬停提示）。
它跟 `outline.dangling` **曾经**不是一条路径，而且顶层那个不收节点级的 —— 结果是对象深处
一条落空的 `@CurrentLevel` 引用只表现为「那个对象变成孤立模块」，失效引用那一栏一声不吭。
用户报的就是这个（游戏读到落空的引用会闪退）。现在 `outline.build` 收尾时把节点级的
`dangling` 和 `notes` **都**汇总进顶层，带上出处；树上的 ⚠ 和「失效引用」那一段终于是
同一份数据。`check-level.js` 里两边都有断言 —— `nodeOf` 那半边单独钉着，因为顶层数字
对不上时它照样能错。

#### 点一行跳到哪儿：按结构定位，不按名字搜

点对象树上的一行要跳到文本里那个对象。原先的做法是 `text.indexOf('"别名"')` ——
**找第一次出现**。可这个名字往往不是先以"那个对象的身份"出现的：

```
"Name": "WidgetProps"                      别的对象里一个值恰好叫这个
"PlantType": "..."                         一个键名恰好叫这个
"Modules": ["WidgetProps@CurrentLevel"]    一条引用（不带引号的兜底那一搜必中）
```

于是点「WidgetProps」跳到的是别处的一个字符串，不是那个对象自己 —— 落在哪儿取决于
这个名字有多常见，是碰运气（用户 2026-09-22 报的）。现在走 `js/level/spans.js`：
从文本里扫出每个顶层对象的字符区间，按**第几个对象**定位。索引是白拿的 ——
解析出来的 `objects` 数组顺序就是文本里的顺序，大纲节点上挂的就是这批实例里的某一个。

两条配套的规矩：

- 区间扫不出来（文本刚改成坏的、形状不是 `{"objects": [...]}`）就返回 `null`，
  调用方退回按名字搜。**宁可跳得糙，也不能不跳**。`main.js` 里那层守卫还多一句：
  `ZLevel.Spans` 整个不在时也退回 —— 这条路径在**插入**之后也会跑（插完跳到新对象），
  抛出去的表现是"点插入什么都没发生"，比跳错地方糟得多。
- **引用**（失效引用那一行的 rtid）继续按名字搜：它就是文本里的一串字符，
  没有"对象"可定位，`text.reveal` 那条路留着正是给它用的。

扫出来的区间跟引擎对账：`check-level.js` 逐个对象比 `JSON.parse(文本.slice(区间))`
是不是正好等于解析出来的第 i 个对象 —— 一边是我的扫描器、一边是 `JSON.parse`，
不是自己跟自己比。`N29`（区间少一个字符）和 `N30`（转义引号不跳下一个字符）
证明这条比法真的能红。

侧栏的**骨架是两列**（`css/app.css` 的 `.app` / `.shell`）：左列是侧栏，从顶上贯通到
底；右列 `.shell` 才是 topbar / 编辑区 / 状态栏那一摞。原先侧栏住在「topbar 下面那一行」
里，于是它顶上永远空着一条顶栏高度的空白。940px 以下侧栏收成 fixed 抽屉，那一列随之
收掉（`grid-template-columns: 1fr`），否则左边会留一条 310px 的空列。

**「顶上留白」这个毛病被报过两次**：第一次是宽屏（上面那两列网格就是修它的），改完
宽屏之后窄屏抽屉还留着 `top: var(--topbar-h)` —— 同一句话换了个断点又报了一次。抽屉现在
也是 `top: 0; bottom: 0`，跟宽屏那一列一样贯通到底。代价说清楚：**☰ 在顶栏最左边，
抽屉一开就把它盖住了**，所以关抽屉只能靠点遮罩（`.scrim` 是 `inset: 0`，顶栏那块也算）
或者再切一次页签。想保住 ☰ 就得让它从那 50px 下面开始，而那正是要修的东西 —— 这是
抽屉这层必须挑一边的取舍。

这条**只能在样式表上验**（`check-editor.js` 那条静态断言 + `npm run mutate` 的
M24/M25 盯着）：jsdom 不做排版，`position: fixed` 的实际盒子它拿不到，「抽屉顶上有没有
那 50px」在无头环境里完全没有观测面。

面板里的字号走**一条固定的梯子**（写在 `css/app.css` 里）：页签和汇总条 `.9em`、
段落标题/叶子行/段尾按钮 `.86em`、段落说明 `.8em`，基准是 `body` 的 15px。段尾的
「清理这 N 个孤立模块」原先走顶栏那套 `.btn`（15px），比它所在的那一段正文还大。

原先的「校验」页撤了。它五张卡片里三张（孤立模块 / 失效引用 / 参考文件里没有）在对象树上
**原样已有**，而且树上那版更好用（每行可点、能跳到文本、孤立模块还带行内 ✕）。
剩下两张各有去处：汇总条搬到树顶上（树的各段分开报数、还可能折起来，没有这一行就得自己加），
模块冲突补成树上的一段，`s.parseError` 那张卡片**删掉**（顶上 `#errbar` 已经在大声说同一件事）。

拆的时候踩到一个旧坑，值得记：**孤立模块不能用 `outline.orphans`**。
`computeReachableObjects` 在没有 `LevelDefinition` 时返回**空 Set**，于是 `Outline.build`
会把整份文件的每个对象都判成孤立模块。对象树上没露馅，只因为 `tree.js` 在无根时提前 return 了；
新开的汇总条住在树**外面**，用错口径就会在一份没有 `LevelDefinition` 的文件上打出
「N 个孤立模块」的红字。所以汇总条一律走 `Parse.findOrphanedObjects`（它带 `hasRoot` 守卫）。
`check-level.js` 和 `check-boot.js` 里各有一条断言盯着这个。

#### 模块详情是一张**插入表单**，不是一个说明书

点模块那一行的浮层，第一版只念值（"插入时会写 `8`"），想改得插完再去文本里找。
现在标量键直接可改，改完按插入，写进去的就是改过的值；顶上那条「已改 N 个键」是唯一的反馈。

**「还原回默认」那一套整个没有了**（2026-09-22 用户：「编辑页面去掉所有还原回默认的相关功能」，
选范围时明确了**两档都去掉**）：原先每行有一个「↺ 默认」（插入那一档 = 退回骨架默认值，改参数
那一档 = 退回**打开时的值**），改过东西时顶上还多一条「全部恢复默认」。连带没掉的：`resetBtn` /
`resetAll` 两个函数、`.mdl-reset` / `.mdl-resetall` 两个类名和它们的样式、那个把按钮顶到右边的
`div.grow`（`.grow` 别处还在用，CSS 那条留着）。**顶上那个计数留着** —— 它不是还原功能，而且
现在它是屏幕上唯一能看出"我动过东西"的地方，见下面那条视觉后果。

这一刀砍出来的两个后果，都是**有意留下**的，别当成没做完：

- **改过的行不再有任何视觉标记。** 样式表里原先写着"改过的值不是靠颜色区分的，靠多了个
  ↺ 默认" —— 那个标记就是它。要恢复"哪几行改过"的可见性得另加一条（比如改过的行换个底色），
  没加。
- **「＋ 按默认值加上」变成单向的。** 加上的键原本只有那一行的 ↺ 能撤回，现在只能关掉浮层
  重来。用户知道这件事（选范围的那一屏里写明了"会变成单向操作"），要留口子得单独说。

**侧栏那一行是三行**（2026-09-22 用户点名改的）：**中文名 + 标签 / objClass / 灰字提示**。
第一版把名字、objClass、标签、说明全挤在一行里，而侧栏只有 200 多像素宽 —— objClass 是等宽
长串（`WaveManagerModuleProperties`），它一挤就把标签顶到看不见的地方，而"这一行叫什么、
插进去是什么类"反倒分不出来了。同一轮里**分组底下那段灰字（`g.note`）去掉了**（用户：
「分类下的 note 多余，就是每个关卡这些灰字」）：插入一个模块是干什么的，说明该挂在**那一行**
上（`row` 的第三行），挂在组头上用户得自己在组里对照哪句说的是哪一个。标签眼下只有三个
（`核心` / `容器` / `引用`）：**`可多个` 那个标签去掉了**（同一轮，用户：「allowMultiple
不显示标签提示」）—— "能不能插第二个"不是读标签读出来的，是浮层里那句"会相互覆盖"
说出来的（见下）。

**控件按默认值的形状挑，不按键名的意思猜。** 形状只有一个来源：骨架里的默认值
（`true` → 勾选框、数字 → 数字框、字符串 → 文本框）。这一层永远不会错，因为它跟插入写进去的
东西是同一份数据。`check-boot.js` 那条断言也是这么对的：拿 DOM 里画出来的控件去对骨架里的值，
一边页面、一边数据，不是把"按形状挑"这个规则重算一遍。

**数组和对象一律走「结构值」那一档。** 最早这一档是**只读**的（原文照抄 + 一句实话
"这个键的专用填写界面还没做"），理由是"不给 JSON 文本框 = 不装懂"。**2026-09-22 用户改了口径**
（原话：「带有结构的框去掉上面结构值图样和现在是下面这段这行字，**允许修改**」），
于是换成**一个可编辑的框**：表头那两行字（「结构值」标签 + 「现在是下面这段」）和底下那句
实话一起去掉，用户看到的直接是这个键现在的值，改它就是改它。

那把"看着像界面、实际会写进一份坏数据"的担忧没被丢掉，只是**移到了解析闸门**上
（`setStruct`）：`JSON.parse` 不通过就当场把提交按钮按下、把原因写在按钮上面，那个键
一个字节都不写 —— 能按下去的一定解析得开。这跟数字框那条（`setNum`）是同一个约定。
⚠ 它是 `<textarea>`：**内容要用 `.value` 读**，`textContent` 永远是空的（初始子文本节点），
自检里踩过这个坑，两处读点都写成了 `.value` 并留了注释。

**框的高度是按内容给的**（2026-09-22 用户：「之前的结构化文本可编辑框默认高度太低，不太长的
情况下至少得显示完整代码」）。原因很直接：`<textarea>` 不给 `rows` 就是浏览器默认的**两行**，
一段十来行的 JSON 打开只看得见头两行 —— 而这一档恰恰是"自己动手填"最费劲的地方。
现在 `fitStruct` 按内容的行数给高度（下限 3 行、上限 12 行），短的整段看得见，长的由
CSS 的 `max-height: 180px` 兜住、框内滚。风格跟别处一致：**高度只在内容真变了时才重量**
（`refresh` 里先比 `.value`），不然用户自己拖出来的高度会被下一次重画抹掉。

**专用控件（坐标格子 → 记录表格 → 图鉴选择器）仍然排在后面**，它们是**更好的填写方式**，
不是"唯一的填写方式"：有了这个框，用户今天就能改结构值；每落地一档就替换掉对应键的兜底，
判据来自 key-schema（元素字段表，从 Kotlin 抽）—— 骨架只说得出"这个键是个空数组"，
说不出里面每条的字段。那一层还没落地，所以**眼下所有结构值键都走兜底**，这是有意的，不是漏了。

（这一段原先是"插完把光标落到浮层里挑的那个键上"，`spans.js` 里还专门有个 `keyRange` 一层层
缩小区间找那个键。2026-09-22 用户点名删掉："多余功能，光标按之前逻辑在原插入位置就行" ——
`keyRange` 跟它一起删了（它只有这一个调用方，留着就是没断言的死代码），`revealCreated` 现在
只做一件事：选中刚插进去的那个对象的**整段**。落点对不对仍然验的是两半：右边那段解得开、
左边紧挨着的得是它的键名。）


#### 同一个浮层的另一半：点对象树上的 ✎ 改**已有对象**的参数

「改参数」那一档跟插入表单**是同一张表**（同一个键表、同一套形状控件、同一份中文说明），
差别只有行从哪来、写回什么：

| | 插入（`mode='insert'`） | 改参数（`mode='edit'`） |
|---|---|---|
| 行从哪来 | 插入骨架 `data/module-skeletons.js` | 这个对象**当前的 objdata** |
| 写回什么 | 整棵 objdata | **只写改动过的键** |
| 按下去 | 插进关卡、跳过去 | 改文本里那几个值、跳回那个对象 |
| 「代号」那一格 | 有新对象的代号，预填元数据里的默认别名（2026-09-22 起；见下） | 首别名；改它 = 本文件所有指向它的引用一起改 |

**「代号」那一格两档都有**（2026-09-22 用户：「新建模块界面也要支持代号命名」）。插入那一档
预填**元数据里的默认别名**（看得见，用户才知道插进去叫什么），而且**没动它就传 `null`** ——
走的还是"默认别名 + 去重"那条老路（`base` → `base1`）；动过才按填的来。这条分界是必须的：
把"没动过的默认别名"递下去会跳过去重，插第二个「可多个」的模块当场撞名被拒，而用户什么都
没填。**填了的时候撞名一律拒绝，不静默加序号** —— 用户亲手打的名字被换成别的，跟"没填代号"
是两码事，屏幕上还什么都看不出来。形状闸跟改代号那条是同一个 `aliasProblem`。

> 早先插入那一档**没有**这一格（理由是"代号是元数据算出来的，填了也不会被用上"，变异 `N51`
> 守的就是它）。用户要求两档都能命名之后这条翻案，`N51` 连同它守的断言一起作废 —— 见下面
> 「变异测试」那一节的记账。

行从 **objdata** 来，是因为要改的是**这个对象**的参数：骨架说的是"新建出来长什么样"，
拿它当行表的话，用户在界面上会看不到自己（或游戏）后来加的那些键，而界面上一
点异样都没有。反过来，骨架里**有**而对象**没有**的键单列一行（`.mdl-absent`），一行一个
「＋ 加上」—— 按骨架默认值补上。**"这个对象没填"只有一个判据**（`isPresent`）：早先那里写的是
`r.present === false`，于是刚点过「＋」的行**同时**算"有值"和"没填"，两个说法对不上，
屏幕上那个数就是错的。

只写改动过的键，是因为浮层开着的时候用户完全可能在右边的编辑器里手打几笔 —— 整棵写回去
= 拿打开那一刻的快照把那些改动盖掉。而且"我没动这个键"和"我要把它写成默认值"是两件事。

**这一档底下不再解释"键名和值是从哪读出来的"**（2026-09-22 用户：「编辑栏里"键名和值都是
从"的这句话删掉，留着没意义」）。上一格那张表已经把两档的差别写清楚了，而站在浮层面前的
用户不需要知道行表是从 objdata 还是骨架来的 —— 他看到的行就是他要改的行。插入那一档底下
**平行的那一句留着**（`d.mode === 'auto'`）：那句开头也是"键名和值都是从……"，但它后面挂的是
"这一档还没有人工说明 —— 给 ModuleDocs 写上中文这里就换一版"，这是**待办提醒**，不是来源
说明；用户指的是"编辑栏"那一档，所以只删了那一处。少这一行不影响任何行为，`check-boot.js`
断言的是**插入**那一档的句子，所以这一处没有断言因此变红。

一个对象在文件里的身份是 **(位置, objClass)**：位置是 objects 数组里的下标（解析不重排，
所以它就是文本顺序），objClass 是复核。保存那一刻拿这两个去当前解析结果里认人，认不上就
**拒绝并说明原因**，绝不"差不多就写这个吧"。

#### 改代号：改的是本文件里**所有指向它的键**

手改一处别名、漏改十处引用，改完就是一串悬空引用，而屏幕上一点异样都没有 —— 这是图形界面
替文本模式补的那一层（上游 Z-Editor 的 Kotlin 侧没有这个功能，是网页版自己的补偿）。
两道闸都在**改之前**：

- **形状**（`Edit.ALIAS_RE`，面板自己实时判）：白名单 `[A-Za-z0-9_-]`。来由是仓库里真实存在的
  4789 个别名（`reference/*.js` 4706 + 内置模板 83），用到的非字母数字字符只有 `-` 一个。
  非拦不可：混进 `@` 就出现三段式 `RTID(a@b@CurrentLevel)`，而 `rtid.js` 头上记着 `parse` 和
  `collectRefs` 对这种形状的切法**故意不一致**；混进 `(` `)` 会让扫描正则（括号内不含括号）
  整个漏掉它，引用当场从可达性里消失，那个对象就成了"孤立模块"等着被清掉。
- **撞名**（只有 `main.js` 判得了，它才看得到整份文件的对象列表）：`Parse` 的可达性分析、
  对象树、`findOrphanedObjects` 全是**按别名认人**的，两个对象共用一个名字之后这一堆分析
  都在猜。老代号被两个对象共用时同样拒绝 —— 那是在替用户猜"你到底想改哪一个"。

**只认 `@CurrentLevel`**：`RTID(Foo@LevelModules)` 指的是**别的文件**里的 Foo（`refs.js` 的三分
口径），把这条也一起改，就把一条本来指得对的引用改成了别的文件里不存在的东西 —— 而那一类
属于"外部引用"，分类上根本不报，只有游戏里读不到。`renameAlias` 里的来源比较是**一个字一个字
比**的，`N43` 钉的就是它。

**指向别处的模块干脆不让改**（2026-09-22 用户：「指向 levelmodules 或其他地方的模块不能重命名
代号，因为参考文件是不能被同步改名的」）。上面那条"只认 `@CurrentLevel`"是**改的时候**不碰
外部引用，这一条是**连入口都不给**：`defaultSource` 不是 `CurrentLevel` 时，「代号」那一格是
灰的（两档都灰），底下那句灰字说明原因（"对象定义在 LevelModules 里，代号说的也是那个文件里的
名字"）。判据只有一处：注册表那条的 `defaultSource`。第二道闸在 `Edit.insertModule` ——
填了代号的 `foreign-alias` 一律拒绝，因为接缝不只浮层一个调用方。
注册表里**没有**的 objClass（没建模的对象）**不算**"指向别处"：它就在本文件里，改名的后果
只在本地，照旧让他改。

改名和改键是**同一次**结构操作（`applyStructural` 一次 = 一步撤销），所以按一次「保存」，
一次 Ctrl+Z 就能全退回去。

#### 浮层底下那几条提示：灰字说"表是怎么来的"，警示色说"按下去会发生什么"

插入浮层底下会挂几条提示，分两档（`mdl-note` / `mdl-note-warn`）。灰字那一档说的是键表
的来路（"键名和值都是从插入骨架读出来的、还没有人工说明"、"这份关卡还没有波次"），
读不读都不影响按不按；
**警示色那一档说的是按下去会发生什么**，所以排在前面、带色，用户按之前得看见。警示色眼下有
三条（哪一条出现取决于那一行是什么模块、这份关卡里已经有什么）：

1. **两个同类模块会相互覆盖。** 非 `allowMultiple` 的模块重复插入**不再被拒**（2026-09-22
   用户：「已有不可重复模块的话允许插入但是要提示会相互覆盖」）—— 一份关卡里挂两条同类模块、
   运行时只有一条生效，是游戏认的一种写法，编辑器不该替用户拦掉它。插入照常（别名走去重：
   `base` → `base1`），提示说的是实话：两个都挂进了 `Modules`。
   `allowMultiple` 的模块**不提示** —— 它们本来就能共存，那不是需要提醒的状态。
   判据只有一处（`Edit.moduleExists`，问的是"默认别名是不是已经被占着"），跟插入时的去重
   用的是同一个：两边各判各的，屏幕上那句话迟早跟实际行为分叉。
2. **插波次管理器会顺带建一个波次容器**（见下）。
3. **波次容器已经有一个了** —— 那一格按下去会被拦（一份关卡只许一个）。

#### 波次容器：一个"不是模块"的条目，加一条没人指得着的引用

波次管理器的 `WaveManagerProps` 键是个 RTID，指的是**另一个对象** —— 波次容器
（objClass `WaveManagerProperties`），波次列表（`Waves`）和那几个倒计时参数都挂在它身上。
它**不在** `LevelDefinition.Modules` 里（9 份真实模板没有一个把它列在 Modules 下），也不算
模块类（`ModuleRegistry` 里没有它）。原文（2026-09-22 用户报的）：

> 波次管理器要特殊设计，因为创建时直接挂载了波次容器模块，但是现在没有 ui 入口允许创建波次容器模块。

原状是：插入波次管理器时，`insertModule` 把骨架里那条 `WaveManagerProps` 改写成"本文件里实际
那个容器"的别名，找不到就退回字面量 `WaveManagerProps` —— 于是落下去一条**谁也不指得着的
引用**（对象树「失效引用」里多一行），而用户没有任何入口把它变好。两处修：

- **注册表里多一条「波次容器」**（`data/modules.js`，标签是虚线的「容器」）。它不是模块，
  所以带两个开关：`isContainer` —— 插入时**不进 `Modules`**，而且一份关卡只许一个
  （第二个容器没有任何东西指得到它，那是纯垃圾）。
- **插波次管理器时顺带建一个**（`main.js` 的 `doInsertModule`：这份关卡一个容器都没有的话，
  先建容器再插管理器）。会多出一个对象这件事写在警示提示里，toast 也会说"并建了一个波次容器"。
  这个副作用**只在 main.js 这一层**有 —— `Edit.insertModule` 是纯逻辑，直接调它的人（自检就是）
  拿到的还是原来那个行为。
  建失败不留半个东西：`applyStructural` 在 `ok:false` 时**一个字节都不写**，连同刚建出来的
  容器一起不算数。

容器的初始 objdata（`Waves` 只留一波空的）在 `data/module-skeletons.js` 末尾，**是手工补的一条**
—— 它不是模块类，生成器永远不会产出它。那条头上写着"重新生成本文件之后必须补回来"，
理由也写在那儿：查不到骨架的表现是"按插入什么都不建"，而页面上一点异常都没有。

建出来的容器落在**管理器紧下面那一格**（`Edit.moveAfter`，跟插入同一次 `applyStructural`，
所以撤销仍然是一步）：`insertModule` 是 `objects.push`，先建容器再插管理器的话容器会跑到管理器
**上面**去。这个落点是照着真实模板定的 —— 9 份模板里同时有容器和管理器的 5 份，容器**五份全在**
`managerIndex + 1`。原文（2026-09-22 用户）：

> WaveManagerProperties 创建时放在 WaveManagerModuleProperties 下面，对象菜单里各个波次
> 做成可折叠状态放在波次管理器次级菜单里。后面有其他含有内联的模块也要参考这种设计，
> 比如挑战模块。目前的挑战模块中挑战模块还为空，下一轮来设计怎么搬过来

在对象树上（`tree.js`）：**波次不再是顶层段落，改成「波次管理器」段里的子段**（`.sec-sub`，
自带缩进和一条竖线，太浅的话看不出"它在那个段里面"）。以前每一波跟管理器段平级，看第 8 波
有什么事件要上下找两处，而它们本来就是同一个对象（容器）的 `Waves` 数组切出来的。
几处细节都是为这次嵌套补的：

- 子段各自还是**可折叠**的（`collapsed` 的 key 照旧是 `'wave1'`…，跨重绘保留），点第 1 波
  不会带着第 2 波一起收；收起父段则容器和所有波次一起藏起来。
- 父段**默认展开**（`section` 新加的 `opts.open`）：`count` 传 `null` 的段落本来默认收起，
  而波次以前是默认展开的顶层段落 —— 照旧规则走的话这一改等于把波次全藏起来。
- 容器那一行就是父段里的第一行（它是"波次管理器"这件事的主体），后面才是各波。

「后面有其他含有内联的模块也要参考这种设计」这句先记在这儿，见 [待办](#待办)。
挑战模块目前是空壳，下一轮再设计怎么搬。

#### 图鉴的入口和浮层为什么"建一次、永不重建"

侧栏其他面板都是**整块重建**的（`tree.js` 以 `host.textContent = ''` 开头），
重建就丢输入框内容、焦点、展开态、滚动位置。对象树靠模块级的折叠状态兜住。

图鉴两条都用不上，因为它跟**文档状态毫无关系** —— 关卡的增删改不会让图鉴多出一条植物。
所以 `main.js` 的 `onStateChange` 里**没有**这个面板；它由 `wireTabs` 在首次切到该页签时懒建
（一个浮层最多要画 1048 个按钮，而 boot 阶段已经扛着 7.6 MB 参考数据）。

「模块」页现在也是**建一次、永不重建**，理由同一类：它唯一随关卡变的东西是"插到第几波"
那个下拉，而那个下拉搬进浮层了，浮层每次打开现问一次 `onWaveCount()`。于是侧栏跟文档状态
也脱了钩，`onStateChange` 里同样没有它 —— 用户展开过的分组不会因为插了一个模块就自己收回去。

拦住"顺手重建"的是 `ensure()` 开头那句 `if (built) return;` —— **它是承重的，不是省几毫秒的优化**：
去掉它，切走再切回来就会重置 `ui`，打开的那一类当场丢；而且会往 `body` 里**再 append 一个浮层**
（每个入口各建一个 = 往 `body` 里叠一堆，扫雷的 `querySelectorAll('.codex-modal button')` 会把它们全捞回来，
`codexModal()` 拿到的却永远是第一个、陈旧的那个）。`check-boot.js` 的侧栏那一节钉着这两件事，
`npm run mutate` 的 M14 / M14b / M15 证明那几条断言确实是活的。

多选（勾选若干条一次插入）本轮**不实现、只留接缝**：插入回调收的是**数组**，
多条一次 `dispatch` 才是关键 —— 分 N 次会变成 N 步撤销。浮层底下那条永远藏着的
`.codex-foot` 就是给它留的位置。

### 撤销 / 重做：全站只有一条历史，就是 CodeMirror 那条

打字和结构操作**本来各有一套撤销**，而且都不完整：CM 自带的那条管打字，但每次结构操作
都用 `view.setState()` 整篇换文本 —— 那会连历史一起清空（实测 `undoDepth` 1→0），
于是每插一个模块，之前打的字就永远撤不回来了；`state.js` 自己攒的那条管结构操作，
**没有重做**，而且按钮上写着「撤销」却只撤得动结构操作。

现在并成一套：

- **结构操作写回走 `dispatch` + `isolateHistory.of('full')`**，历史保住，这次操作自成一步。
  这两点缺一不可 —— 不带 `isolateHistory` 的话整篇替换会**并进前一次打字的分组**
  （改动区间重叠 + 间隔远小于 `newGroupDelay` 500ms），一次撤销把打字和插入一起退掉。
  用 `'full'` 而不是 `'before'`：还要挡住**后面**接着打的字并进来。
- **只有「换文档」才清历史**，走 `resetText`（`setState`）。注意它**不能**做
  「文本相同就跳过」的短路 —— 打开一份内容恰好相同的文件时，历史必须照样断掉，
  否则还能撤销回"上一个文件"。
- 键位由 `basicSetup` 绑好（`Mod-z` / `Mod-y` / `Mod-Shift-z`）。但焦点不在编辑器里时
  （比如刚点完侧栏的「插入」按钮）它们不生效，所以 `main.js` 另挂了一个 document 级
  `keydown`；它靠 `e.defaultPrevented` 让开 —— CM 处理过的它不再做第二遍，否则一次退两步。
- CM 的历史不存元数据，所以 `text.js` 另维护一份平行的 `labels[]` 给按钮当提示语
  （「撤销插入」/「重做删除」）。它是纯函数 `Text.syncLabels`，因为纯才塞得进
  `check-editor.js` 的裸 `vm` 里逐个用例钉死。
  两个不变量：`labels.length === undoDepth`，深度 `d` 的名字在 `labels[d-1]`。
  最阴的一处是 CM 的历史有**条数上限**（实测 120 条时一次性从**前面**丢 19 条），
  标签必须跟着左移而不是从尾巴截 —— 按尾巴截会从那一刻起整体错位，且每撞一次多错一次。
- **两个按钮常驻顶栏，不可用时置灰（`disabled`）而不是藏起来**（`index.html` 上写死
  `disabled`，`renderStatus` 只翻转它）。藏起来会让顶栏按钮忽左忽右地跳，用户也没法从
  「按钮没了」分辨出是"没东西可撤"还是"这功能不在这儿"。置灰的样子在
  `css/app.css` 的 `.btn:disabled`。

### `hidden` 为什么会不生效（"顶上一块红框"那个 bug）

用户报过：没有语法错误时顶上还是有一块红框，而且报错改好了、文字还留在上面。

根因不在 JS，在**来源优先级**：浏览器默认样式表里那条 `[hidden] { display: none }`
属于 UA 来源，而**作者样式表里任何一条设了 `display` 的规则都能盖掉它** —— 跟选择器
优先级无关。`.errbar { display: flex }` 这么一写，`bar.hidden = true` 就成了摆设：
元素照样占着位置、照样是红的，只是内容不再更新。

两处一起改，各管一边：

- `css/app.css` 加 `[hidden] { display: none !important; }` —— 这才是真让横幅藏住的那条。
  `hidden` 属性表达的本来就是"别显示"，在这里用 `!important` 是对的用法。
- `renderErrorBar` 把 `bar.textContent = ''` 提到提前 `return` **之前** —— 就算哪天
  又冒出条 CSS 把 `hidden` 盖掉，用户看到的也顶多是一条空带子，不会看到过期的报错文字。

这个 bug 在 jsdom 里 **100% 隐身**：它的 `getComputedStyle` 自己认 `hidden` 属性，
样式表坏掉时照样报 `none`（写了个探针实地确认过）。所以回归测试只能是**静态读样式表**
（`check-editor.js` 里那条 `[hidden] 上有一条 display:none !important`），
`npm run mutate` 的 M11 证明它确实是活的。


## 保真：网页版跟 Z-Editor 是什么关系

这是整个项目最要紧的一节。桌面版编辑器和网页版**同时存在**，用户会在两边改同一份
关卡文件，所以行为必须对得上，否则文件会在两边来回改动中悄悄变形。

### 文本编辑写的是字节，结构操作才重新序列化

- **手打的字，保存时原样落盘**。编辑器不做「读进来 -> 解析 -> 重新序列化」那一套。
  所以你在文本里留的 `1.0`、属性的原始顺序、缩进，保存后一个字节都不变。
- **结构操作**（插入模块/事件、删对象、清孤立模块）必须重新序列化整份 JSON，因为对象顺序
  要按游戏的加载顺序重排。这一步会把数字写法规范化（`1.0` 写成 `1` —— 两者是同一个数，
  不是数据丢失）。

这个区别在界面上是**看得见的**：做过结构操作之后状态栏会出现「已做过结构操作」，
悬停有解释。宁可多一句话，也不要让用户以为保存把文件弄坏了。

### 判定逻辑照抄，一处不落地对着 Kotlin 核

移植时不是「看着像就写」，而是把 Kotlin 源码读出来逐条对照。这样做抓出了 **Z-Editor
自己的两个 bug** —— 网页版没有照着复现，而是**按意图修掉了**，都在代码里留了注释：

1. **坚不可摧不自动打开 ManualStartup**。它判的是
   `meta.defaultAlias == "LastStandMinigame"`，但注册表里
   `LastStandMinigameProperties` 的 `defaultAlias` 是 **`"LastStand"`**，
   全仓库没有任何模块叫 `LastStandMinigame` —— 那个分支从来没执行过。
   网页版改成按 `objClass` 判定。
2. **地底出怪的骨架少了两个字段**。`SpawnZombiesFromGroundSpawnerProps` 的工厂写的是
   `WaveActionData()`（没有列范围），但同一个注册项的 `summaryProvider` 解析的是
   `SpawnZombiesFromGroundData`，后者 `ColumnStart=6` / `ColumnEnd=9` 且非空。
   网页版的骨架按 `summaryProvider` 的形状给。

这两处都不影响网页版读旧文件，只是新插入的对象更符合游戏预期。

### 契约闸：写进去的键名必须真的是游戏认的

移植时我自己犯过一次错：把 `WaveManagerProps` 写成 `waveManagerProps`、
`ManualStartup` 写成 `manualStartup`。**测试全绿** —— 因为实现和断言用的是同一个
错名字，自己跟自己自洽。

所以 `tools/check-level.js` 里加了一道「不信任自己」的闸：结构操作写出来的键名，要拿去
跟**外部真源**对账 —— 骨架文件里的字段、和真实模板文件里的字段。写错名字会被这条拦下。
同类闸门还有 `RTID_TABLES` 白名单（表名写错不会抛错，只会静默复制出错的 RTID）。

**模块注释那道闸**（`tools/check.js` 的「模块注释」一节）是同一个道理的第二次应用：
模块浮层的键表是**自动读的**（插入骨架），中文说明是**人写的**（`data/module-docs.js`），
两边分叉不会有任何症状 —— 词条里抄错一个键名，浮层上就多出一行**插入结果里根本没有的
假键**，而那一行是照人抄的样子画出来的，看不出真假。所以词条的形状是**稀疏**的：

```js
window.ZEditor.ModuleDocs = {
  SeedBankProperties: { desc: '……', keys: { SelectionMethod: '选卡方式：chooser / preset' } }
};
```

人只写中文，键名和默认值一律从骨架读，行只可能来自骨架（**v1 那种 `{key, type, doc}`
的数组形状不再被认**：它自带键名，正是假行的来源）。词条里写歪的键名由自检报出来，
面板**不校验** —— 页面不该去校验自己的数据。

`data/module-docs.js` 的打底由 `tools/gen-module-docs.mjs` 生成：79 个模块 / 232 个键，
键名全在、中文**全是空串** —— 这份文件是给人当清单填的。所以那个脚本是**合并**不是覆盖：
重跑先读现有文件，写好的中文原样留着，只补骨架里新冒出来的键；骨架里删掉的键、注册表里
没有的词条都原样保留（挪到文件末尾）并打一行警告，交给闸门去报 —— 人工写的东西不该被
脚本悄悄扔掉。（`gen-modules.mjs` / `gen-templates.mjs` 是覆盖式的，因为那两份是纯生成物。）

空串有一条界线：`''` 是**有意的空位**（还没写），闸门不报 —— 打底文件一生出来 232 个键
全是它，报了这里就成了一台见谁报谁的机器；`'  '` 才报，因为浮层那一行是真值判断，
一串空格会画出一行**看着空着**的说明。填了多少另打一行 `--`（`填词进度：0/232 个键有中文`），
那是进度，不是通过。
（**2026-09-22 这一轮从 224 涨到 232**：手工补进骨架的「波次容器」重跑打底时补了 8 个空位 ——
`79 个模块 / 232 个键，新补了 8 个键`。写好的中文一个都没动。）

**「待添加注释」那个占位只摆给"在列"的键**（2026-09-22 用户点名的：「待添加注释这里只应用
在已经注册在列确实需要添加注释的模块，而不是遇到一个没见过的模块也显示待注释」）。
判据是**这个键在插入骨架那张名单里**（`docLine` 看的 `r.docSlot`），不是"这个模块在不在
注册表里"、也不是"ModuleDocs 里有没有它的词条"：

- 骨架**就是那份键名单**，而契约闸只认骨架里的键名（不在骨架里的键写进 ModuleDocs 会被
  报"键名抄错了"）—— 也就是说，不在这张表里的键**根本注不进去**。给它摆一个「待添加注释」
  等于指着一个填不进去的格子催人填。
- 改参数那一档的行有一半来自**对象自己的 objdata**，而真实模板里确实有骨架里没有的键
  （`WaveManagerModuleProperties.ManualStartup`、`SeedBankProperties.ZombieMode`、
  `WaveManagerProperties.SuppressFlagZombie` 等等，9 份模板里共 6 个模块有这种键）。
  没建模的 objClass（`ZombieType`、`ProjectilePropertySheet`、`LevelDefinition` 这类）
  整个都没有骨架 —— **用户报的"没见过的模块"就是这一类**，以前它们每行都摆占位。
- 挑骨架而不是挑词条，也省掉一层时序：骨架里新冒出来、词条还没跟上的键，照样该说
  "待添加注释"（那正是要多跑一次 `gen-module-docs.mjs` 的信号）。这一轮就是这么走的 ——
  手工补进骨架的「波次容器」那 8 个键，打底重跑时才补上词条里的空位。

于是屏幕上"没有第三行"和"摆着占位"是两件事，分得开：前者是"这个键没人给它留位置"
（`ManualStartup` 那种），后者是"留了位置、还没写"（那 232 个）。代价是有 `ManualStartup`
这种键的模块里，同一张表会有的行两行、有的行三行 —— 这是照实画，不是画漏了。

那道闸的判定是个纯函数，**它自己也被验了一遍**：自检里拿假数据把它逼红六次（抄错的
键名、注册表里没有的 objClass、旧的数组形状、一串空格、空串**不报**，以及"对得上的词条
一条都不报"）。理由是 `tools/check.js` 那个位置最容易变成一台**见谁报谁**或者
**什么都不看**的机器，而这两种跟"数据干净"在输出里长得一模一样。

### 模板逐字节比对

`data/templates.js` 里 9 份模板是从 Z-Editor 的资源里抽出来的原文。

- **存的文本**与源文件逐字节相同（`data/templates.js` 是生成物，由
  `tools/gen-templates.mjs` 产出；生成时不碰换行符，见脚本里的注释）。
- **解析后再序列化**回来的结果：7 份与原文逐字节相同，1 份只有数字写法差异
  （`1.0` vs `1`，同一个数），1 份因为 Z-Editor 保存时本来就会重排顺序。
  三类差异都有断言钉住，不是「看着差不多」。

### 外部参考文件：`reference/`

关卡的引用是 `RTID(别名@来源)`，来源分两类，**性质完全不同**：

- `@CurrentLevel` —— 对象就在本文件里，找不到才是真出错；
- `@LevelModules`、`@ZombieTypes`、`@PlantTypes`、`@PropertySheets`、
  `@GridItemTypes`、`@ZombieActions` —— **按定义就在别的文件里**。

网页版原先只认本文件，于是把外部引用全判成「找不到引用」：9 份内置模板去重后
153 条引用里有 **71 条是误报**。误报把这一栏彻底变成噪音，真出错时用户已经不看它了。

修法是搬上游那 6 个参考文件（`tools/gen-refs.mjs` 生成 `reference/*.js`，共 7.4 MB），
然后**三分**而不是两分：

| 情况 | 判定 | 界面 |
|---|---|---|
| 有数据 + 别名在 | 引用成立 | 正常 |
| 有数据 + 别名不在 | 可能拼错了 | **失效引用**（`alias-typo` 档，报红） |
| 没数据 | 不判 | 什么都不显示 |

最后一行是关键：上游资产里出现过的来源有二十来个（`@SkillTypes` 2938 条、
`@ProjectileTypes` 1694 条……），我们没有它们的参考文件。硬判这些来源
就是满屏误报。上游 `ReferenceRepository.getLevelModuleAliases()` 在参考文件
没加载时返回 `null`、调用方直接跳过校验 —— fail-open 是上游明确的设计，这里沿用。

**数据是原样嵌进 JS 的**，不是 `JSON.stringify` 后的字符串：`reference/<Source>.js`
里那段就是上游 JSON 的原文（逐字节未改），直接当对象字面量求值。
这么存是因为它同时是「注入式自定义」的数据源，要能原样取到完整对象图；
仓库里那份字节就是上游那份字节，逐字节对账不用先解码。

代价是**裸字面量有几个经典炸点**：`</script`（HTML 解析器会提前掐断脚本）、`<!--`、
U+2028/U+2029、CRLF、BOM，还有一个最阴的 —— 键名 `__proto__`：对象字面量里它是
**设置原型**，`JSON.parse` 里它是普通自有属性，两者字节相同、求值结果不同，
**逐字节对账发现不了**。上游这 6 个文件今天一个都没踩上，但那是快照的性质、
不是我们能保证的，所以 `gen-refs.mjs` 把这几项**逐条断言**，不合格就报错退出 ——
生成一个会白屏的页面才是最坏的结果。

`js/level/refs.js` 是运行时入口。有一条**很脆的约束**：它排在数据脚本**前面**，
所以必须在**调用时**才读 `window.ZLevel.RefData`，别名集合也必须惰性构建。
写成 `var RefData = window.ZLevel.RefData;` 会让整个功能静默失效 ——
失败方向恰好是「不判」，也就是回到误报更少、但什么都不校验的状态，
页面一切正常、没有任何症状。

## 构建

**唯一的构建步骤是 CodeMirror 6**：

```bash
npm install          # 只在需要重新打包 vendor 时跑
npm run build        # -> vendor/cm6.js（411 KB）
```

CM6 只发 ESM，而 `file://` 下 `<script type="module">` 会被 CORS 拦掉。所以
`tools/cm6-entry.mjs` 作为入口，用 esbuild 打成一个 IIFE 挂到 `window.CM` 上，
「双击 `index.html` 就能跑」这条性质得以保留。

`vendor/cm6.js` **是签入仓库的生成物**：日常改代码不需要 `npm install`，
只有要动 CM6 用到的能力时才重新打包。改了 `tools/cm6-entry.mjs` 一定要重新打包 ——
`tools/check-editor.js` 会拿产物里实际导出的成员名单跟代码里的用法对账，
就是被这个坑坑过一次才加的（见下）。

但那个路径写死在作者机器上，所以仓库里放了同样 9 份在 `tools/fixtures/templates/`。
有检出时优先用检出（并顺手对一次账，发现上游模板改了而 fixtures 没跟着更新）；
没有就用 fixtures，并在输出里明说用的是哪一份 —— 不静默降级。
`data/templates.js`（生成物）的内容永远拿来跟这一份对账，所以编辑器「新建文档」写出去的
文本始终是被钉住的。

检出不在默认位置的话，用 `Z_EDITOR_REF` 指过去：

```bash
Z_EDITOR_REF=D:/PVZ2LevelEditor npm run check
```

`check-editor.js` 是**没有浏览器时的替代品**。它查的都是「跑起来才发现」的低级错误：
`getElementById` 要的 id 在 HTML 里不存在、`<script>` 指的文件已删、类名写错、
`window.CM` 上根本没有那个方法……最后一类是被坑出来的：曾经把 `CM.setDiagnostics`
写进 `text.js` 而没重新打包 vendor，语法自检全绿、跑起来波浪线就是不出现。
现在它会直接读 `vendor/cm6.js` 末尾那个 `window.CM={...}` 字面量来对账。

它还会把 `jsonpos.js` / `text.js` / `state.js` 塞进 `vm` **真跑一遍**（这三个模块不碰
DOM），逐个字符钉死「手滑时波浪线画在哪、说什么」；最后按 `index.html` 里的**实际顺序**
把所有脚本加载一遍（配一个最小 DOM 桩），抓「依赖还没加载就去读它」。

最后这条值得说一句，因为它第一版是**假的**：原先写的是「加载完之后看
`window.ZLevel.Edit` 在不在」—— 顺序错了也照样绿，因为那时 edit.js 早加载完了，
而 `main.js` 抓到的是它自己那个 `undefined` 快照。改成给命名空间套 `Proxy`、
在**读的那一刻**记账之后才真正管用。验证方式是故意把 `edit.js` 挪到 `main.js`
后面，确认那条断言会红、而另外两条确实瞎。

## 无头整页：`npm run check-boot`

上面那套不管怎么做，都只能证明「文件之间的关系是对的」，证明不了「页面跑起来是对的」。
`tools/check-boot.js` 补这一块：按 `index.html` 的顺序把 34 个脚本注进 jsdom、触发
`DOMContentLoaded`、等 `boot()` 跑完，然后**真的去点** —— 插模块、从对象树删、
连撤两次再连重做两次、打字后再插模块看撤销是不是一次退一步、换文档看历史断没断、
焦点不在编辑器里时按 Ctrl+Z、打进一个语法错误、切主题。

它一上手就抓到两个「静态检查全绿」的 bug，而且都是**整个页面点谁都没反应**级别：

| 症状 | 真因 |
|---|---|
| 编辑器渲染正常，按钮 hover 有手型，点下去什么都不发生 | `text.js` 里 `themeComp.of(currentTheme())` 在 `var mq = matchMedia(...)` **之前**执行。`var` 提升给的是 `undefined`，`create()` 第一句就抛，`boot()` 当场死掉 —— 于是 `wireTabs` / `wireTopbar` 一次都没跑 |
| 三个面板全是空的（对象树、校验、插入 —— 当时的三个页签） | `state.js` 的 `emit()` 传出去的是**纯数据记录**，`main.js` 的 `renderStatus` 却调 `s.canUndo()`。它在 `onStateChange` 里排第一，一抛异常后面三个面板全画不出来 |

两个都记在代码注释里了。第一条的教训是**顺序**：`var` 声明在下面不等于用得到；
第二条的教训是**契约**：订阅回调收到的东西上没有方法，要方法得去问 `create()` 返回的对象。

写这套东西本身也踩了两个坑，都值得记：

* **事件监听器里抛的异常不会传回 `dispatchEvent`**（规范规定报到全局错误处理上）。
  所以「用 try/catch 包住 dispatchEvent」根本看不见「点了没反应」的真正原因，
  必须挂 `virtualConsole` 的 `jsdomError` 并把**栈**打出来。
* **第一版是个假绿生成器**：断言失败只往控制台打个 `!!`，退出码只看「有没有抛异常」，
  于是断言全红也照样打印「整页跑通」并 exit 0。现在断言失败计入退出码 —— 这是靠
  变异测试发现的：把 `state.js` 的语法错误守卫拿掉之后，断言确实红了，`$?` 却还是 0。

同一轮变异测试还逼出一条弱断言：「语法错误时插入被拒绝」原来只查**文本没动**，
而**抛异常也是文本没动**。现在改成查用户有没有收到那句提示（`#toast` 里有「语法错误」）
且过程中没有异常。

最后一节是「按钮扫雷」：把每个页签里的按钮逐个点一遍，只问有没有抛异常。
这一节写的过程中连着栽了三跤，每一跤都是同一类错误 —— **测的东西悄悄不存在了**：

* 第一版先收集 `NodeList` 再遍历。面板是整块重建的，点到一半节点全成游离节点，
  点的是旧闭包，等于没点。改成每次现查 DOM。
* 第二版号称「扫了 600 个按钮」，其实空关卡是干净的，当时的校验页**一个按钮都不渲染**，
  那 600 下是 96 个插入按钮来回点了几轮。要先造出「脏」文档。
* 第三版造了孤立模块，但扫雷顺序是「树 → 插入 → 校验」：树那边点 `node-del` 会级联、
  插入那 55 下会把文档改得认不出来，哪个先来孤立模块都没了，「清理」按钮跟着消失。

所以现在**覆盖率本身也是断言**：点名要求 `node-go` / `node-del` / `sec-head` /
`ins-group-h` / `ins-main` / `codex-item` / `mdl-insert` / `mdl-mclose` / `btn-fix`
必须真的被点到。这一步才是关键 —— 前三跤里扫雷都是全绿的。

图鉴侧栏另外点名了 `codex-ch` / `codex-fold` / `codex-sec-btn` 三个类。理由不是它们
稀有，恰恰相反：三级目录里**两级**共用 `.codex-entry` 那套排版（80 个次级项 + 5 个类别
行），只点名 `.codex-entry` 的话，"章行一个都没扫到"会藏在同类里看不出来。大类名
（`.codex-sec` + `.codex-sec-btn`）尤其要单独点名 —— 它是 2026-09-22 才变成按钮的，
加个类忘了接线，扫雷不会自己发现（变异体 `N12b` 钉的就是这一层）。

`.codex-item` 和 `.mdl-insert` 现在活在**浮层**里（挂在 `body` 下），
`sweep('#panel-codex', …)` / `sweep('#panel-modules', …)` 永远碰不到它们 ——
这正是"覆盖悄悄失效"的形态，所以两个浮层各单列了一步。浮层还都是**懒开**的：不给 `pre`
先点开一个入口（图鉴点类别入口、模块点一行），`querySelectorAll('.xxx-modal button')`
就是空集，`sweep` 自己不报错，全靠上面那条覆盖断言兜底。

模块浮层那条还顺手钉住了一件事：`doInsert()` 开头有 `if (!ui.open) return;`。扫雷是照 DOM
点的，浮层关着时 `.mdl-insert` 照样查得到、照样点得动 —— 少了那道闸，一次扫雷会在用户根本
没看着浮层的情况下往关卡里插东西。

侧栏重构改掉了第三跤的解法：「清理」按钮从校验页**搬进了对象树**，原先"校验页必须第一个扫"
那份顺序保护随之失效 —— 树这一步自己就会先把孤立模块行删光。现在靠 `sweep()` 的
`firstSel` 参数**显式点名先点**，而不是靠"哪个面板先扫"。

图鉴拆成两步扫：`#panel-codex` 点那 **107 个按钮**（5 个类别行 + 80 个次级项 + 18 个大类名 +
1 个折叠开关 + 顶部三档复制格式 ← 2026-09-22 起大类名也是按钮，90 → 107），
`.codex-modal` 点浮层里剩下的按钮。两步都排最后；
`#panel-codex` 那一步的 `cap` 是 140，107 离它还有余量（用完不是报错，是**悄悄少点**，
所以 `check-boot.js` 里点名要 `.codex-ch` / `.codex-fold` 真被扫到）。浮层那一步的 `pre` 里**先搜一个词**把
结果集压小 —— 点击虽然已经改成复制（不再往文档里插），但**长按仍然会插**，而扫雷是拿
`click()` 点的、只发 click 不发 pointerdown，所以真正要防的是慢：浏览态打开即画完，
最坏 1048 行（僵尸代码，整类一次画完）。

浮层改成整类之后重算过这笔账：`#panel-codex` 那些按钮里每个次级项一点就把**整个类别**
重画一遍，DOM 行数从约 2 万涨到约 6 万。量下来整页 **约 5.2 秒**（`node tools/check-boot.js`，
改之前是 4.8 秒），离 10 秒那条线还很远，所以 `cap` 保持 140 不动。真要涨上去的话，光降 `cap` 是
**又一次"覆盖悄悄失效"** —— 必须同时把 `.codex-entry` 加进上面那份点名覆盖率清单。

浮层那一步的配额从 60 提到了 **140**：浮层里现在多了三档密度、最多 31 个目录索引按钮
（整个类别的次级项数，僵尸代码），60 会在走到 `.codex-item` 之前就用完 —— 而配额用完
`sweep` **不报错**，只是悄悄少点，全靠上面那条覆盖断言兜。这个数写在 `plan` 循环里
`cap` 那一行。（2026-09-22 删掉「范围」按钮之后这里**没有**下调：那个按钮是 1 个，
少 1 个不影响 140 这档余量，而调它要走一遍"重新量耗时"那笔账，不值当。）

它**不能**替代人眼：布局、hover、滚动、真实渲染效果都测不出来。jsdom 也没实现
`getClientRects`，所以 CM 的滚动定位那条路走不到底（会以未实现的错误暴露出来）。

jsdom 还有两处**测不到的东西**，都只能人眼过：

- `isContentEditable` 在 jsdom 里是 `undefined`（`contentEditable` 也没实现），
  所以键盘撤销那条「目标在可编辑元素里就不抢」的判断在无头环境里命中不了。
- **样式表那条 `[hidden]` 规则**。jsdom 的 `getComputedStyle` 自己认 `hidden` 属性，
  样式表坏掉时照样报 `none` —— 也就是说「顶上一块红框」那个 bug 在无头环境里
  100% 隐身。它由 `check-editor.js` 的静态断言 + `npm run mutate` 的 M11 守着，
  再加人眼看一眼：**没有语法错误时顶上不该有任何红色的东西**。

    点树上的行和插完新模块走的是同一条路，所以两处一起变了。
    ⚠ 失效引用那一行走的是另一条路（`reveal`，按名字搜），光标记在短字符串的末尾 ——
    那一处**没动**（用户只说了模块），觉得也要改说一声。

    ⚠ 这一条**只能人眼看**：jsdom 里没有真正的光标，套件那两条断言只看选中区间的
    `from`/`to`（两头都不区分），所以**改前改后都是绿的**，钉不住这件事。

## 为什么错误位置是自己扫的

`jsonpos.js` 自己实现了一个 JSON 扫描器，用来定位第一个语法错误。原因是**引擎给的
位置在最常见的两种手滑上根本没有**：

```
{"objects": [}    ->  Unexpected token '}', "{"objects": [}" is not valid JSON
{"objects": [     ->  Unexpected end of JSON input
```

两条都没有 position / line / column —— 而它们恰恰是打字打到一半的样子。直接取引擎
位置的话波浪线永远画在第一行，比不画还误导。而且三个引擎给位置的形式各不相同
（V8 用 `at position N`，Firefox 用 `at line L column C`），要正确解析得写三套。

扫描器只在 `JSON.parse` **失败之后**才跑，正常打字路径上一次都不执行；它给的错误
消息直接就是中文，引擎原文留在横幅的悬停提示里（它是权威，扫描器只是更会指路）。

## 手机端适配（2026-09-22）

用户报了三件事，一起修的：设备间图标不一样、手机端右半部分被截、界面偏大又缩不了。

### 一、图标：文字字符 → 内联 SVG

原先 12 处图标全是**文字字符**（`✎` U+270E、`✕` U+2715、`☰` U+2630、`⚙` U+2699、
`▾`/`▸`、`›`、`＋`、`⚠`）。画成什么样完全交给设备上装的字体：Android 会把 `✎`/`⚙`
当 emoji 画成彩色的，缺字形时显示豆腐块（`⚙` 风险最高 —— 裸 U+2699 不带变体选择符，
多数移动端按 emoji 呈现）。**同一份代码在两台设备上必然长得不一样，而且这在 jsdom
里测不出来**（它不做排版，更不管字体回退）。

改成 `js/editor/panels.js` 里 `icon()` 造的 SVG。形状表 `ICONS` 是唯一真源，所以
`index.html` 里那几个顶栏图标按钮**是空的**，图形由 `main.js` 的 `wireIcons()` 补上。
颜色走 `currentColor`，主题和 `.node-del:hover` 那些变色规则一条都没改。

⚠ 两个坑：

1. **必须 `document.createElementNS`**。`el('svg')` 走 `document.createElement`，
   在 HTML 文档里造出的是 `HTMLUnknownElement` —— 不报错、不抛异常、**什么都不画**。
2. **折叠三角不能靠改字形切换了**。原先 JS 在 `▾`/`▸` 之间改 `textContent`，SVG 没有
   字形可换。现在只做一个朝右的三角，展开时由 CSS 转 90° —— 条件是父按钮上的
   `aria-expanded`。顺带把 `sec-head` / `ins-group-h` 上缺的 `aria-expanded` 补上了。
   **`tools/check-boot.js` 的扫雷原先正是靠正则找 `▸` 来认折叠段的**，那条判据跟着
   实现走，改用属性之后更结实（改的是 `:3049` 和 `:3167` 两处）。

`panels.js` 因此要排到 `tree.js` **前面**（tree.js 加载期就取 `icon`/`iconBtn`），
`index.html` 里的顺序跟着调了。

### 二、右半边被截：`.shell` 少了一条列定义

**根因只有一条，两个受害处。** `.shell` 原先只声明了 `grid-template-rows`：少了列
定义，三行就共处一个**隐式 `auto` 列**（`minmax(auto, max-content)`），而 `auto` 的
最小值看内容的 min-content。顶栏里全是 `flex: 0 0 auto` + `white-space: nowrap` 的
按钮，min-content 收不下来（约 400~460px，跟平台的中文字体度量有关）；于是那一列被
撑到那么宽，grid 子项又默认 `stretch`，**三行全都按这个宽度排** —— 编辑区不是自己
有毛病，是被同一列连累的，然后被 `html, body` 上的 `overflow: hidden` 裁掉。现象就是
「右边没了，而且没法横向滚」。

修法是给 `.shell` 补 `grid-template-columns: minmax(0, 1fr)` —— 把列的最小值钉成 0。
只给顶栏加 `min-width: 0` 也管用，但那是逐个子项打补丁；列定义这一条是一次性兜底的。
（同一份文件里的骨架注释早就描述过这个失败模式，`.shell` 和 `.main` 都加了
`min-width: 0`，**唯独漏了 `.topbar`**。）

顺带：`.topbar` 加 `flex-wrap: wrap`，放不下就换行 —— 手机端顶栏变两行，**没有新断点**
（768px 的平板仍然一行）。「打开/模板/撤销/重做/下载/设置」收进一个 `.tb-actions` 盒子，
换行时整组一起走；不收的话 flex 会贪心切，把「撤销」单独甩到第二行去。

⚠ **换行之后顶栏多高就说不准了**，而 `--topbar-h` 被三个浮层的 `top` 读着
（`.mdl-modal` / `.codex-modal` / `.popover`，它们是 `position: fixed`，没法用"从某个
元素往下 6px"表达）。做法是 `main.js` 的 `syncTopbarH()` **量一次写回**
`documentElement`，boot / resize / orientationchange / load 各量一次，字号档切换后再
量一次（字号会改按钮宽度 → 改换行位置）。**不在某个断点硬写 92px** —— 顶栏最小宽度在
400~460px 之间浮动，硬编码的断点正好会在这个区间猜错，猜小了照样压，猜大了白留一条缝。

`.shell` 的网格行相应改成 `auto 1fr auto`（内容多高就多高），这样布局**天然正确**，
不依赖 JS 量得准不准；`--topbar-h` 就只服务浮层了。桌面仍然是 50px —— 34px 的按钮
加上下各 8px 内边距。

另外 `index.html` 早就有 `viewport-fit=cover`，但样式表里一处 `env(safe-area-inset-*)`
都没有，刘海屏横屏时右边会被圆角吃掉；顶栏的左右内边距改成了
`max(10px, env(safe-area-inset-*))`。

### 三、字号五档（A− / A+）

手机浏览器**不允许**把页面缩到 1× 以下（`initial-scale=1` 时 pinch 只能放大），所以
「界面太大想缩小」只能由样式自己做。

形状照抄图鉴的排列密度那套：localStorage 存枚举（`zeditor.fontSize`）→ JS 往
`documentElement` 挂 `data-fs` 属性 → 样式表按属性值给 token。**中档 = 属性被删掉**，
回落到 `:root` 上那组基准值（桌面 15px/13px、窄屏 15px/12.5px），跟密度档的 `standard`
完全一致 —— 好处是桌面现有字号一个像素都不用动，也不用去核对两处数值抄对没有。

档位：`xs` 12/10 · `small` 13.5/11 · `medium`（默认，无属性）· `large` 17/14.5 ·
`xl` 19/16（界面 / 代码）。第一版只做了小中大，用户上手就要求「范围再大点」——
两头各差 1.22 倍，而手机上想要的是**缩小**，那一头恰恰下不去；现在 12~19px 是 1.58 倍。
档位名在 `main.js` 的 `FONT_SIZES` 和样式表那四个 `:root[data-fs="…"]` 块里各写了一遍，
**对不上不报错**，只是那一档静默回落到中档 —— 症状是「按了没反应」，先核这两个列表。

图标是固定 px（`.icon-btn` 34px、`.ico` 18px），**不跟着字号缩放**：缩到 12px 时点按
目标还是那么大，不至于变得点不着。

两个 token 一起动：`--ui-fs` 是 `body` 的字号，全站约 70 条 `font-size` 全是 `em`，
改它等于整站跟着缩放；`--code-fs` 单独拎出来是因为 CodeMirror 那 13px 是**硬编码**的，
不接变量就带不动。`body` 的 `font: 15px/1.5 var(--sans)` 简写也拆成了三行 ——
简写里塞 `var()` 要等替换完才解析，某个 token 写错的话**整条简写**失效，字号和行高会
一起掉回浏览器默认值。

## 本地预览 / 部署

双击 `index.html` 即可。要起服务器（比如之后加 Service Worker）：

```bash
npm run dev          # python -m http.server 8000
```

Cloudflare Pages：

| 配置项 | 值 |
|---|---|
| 根目录 | 留空（默认就是仓库根） |
| 框架预设 | `None` |
| 构建命令 | `exit 0` |
| 输出目录 | `.` |

**输出目录填 `.`**（一个点）—— CF 默认去 `public` 找产物，而站点就在仓库根，不覆盖会部署出空站；
`./` 会被拒。**构建命令填 `exit 0` 而不是留空** —— 留空时 CF 可能退回默认行为去跑
`npm run build`，那会真去打包 vendor（慢，而且产物已经签入了）。

`_headers` 是唯一的 Cloudflare 专属文件，管缓存与几个安全头，必须在发布根目录。
**缓存必须设成 `max-age=0, must-revalidate`，不能图省事给 `js/` `css/` 配长时间缓存。**
站点没有内容哈希文件名，「部署清缓存」只清了 CF 边缘节点，管不到访客浏览器里已经存下的副本。
踩过的坑：`/js/*` `/css/*` 配了 `max-age=3600` 之后，`index.html` 是新的而 js/css 是旧的，
表现是**新按钮画得出来但点了没反应**——这种「半个新版本」最难排查。

**换平台几乎零成本**：全部是相对路径，整个仓库丢给任何静态托管都能跑，挂子路径下也不用改代码。

**宽屏下浮层里没有目录列**了（左边那一列跟侧栏那三级作用重复，用户点名收掉），
所以宽屏的浮层就是「搜索框 + 一整个类别的列表」。

窄屏（≤939px）下目录**回来**，是顶上一行横滑的 chip（同一元素，
见下面「次级目录」一节）—— 窄屏侧栏是个关着的抽屉，这一行是唯一还看得见的分组导航：

```

│ 条目列表：点击复制、长按插入（打开即画完，不分页）    │
└─────────────────────────────────────────────────────┘
```

- 大类就是图鉴原来的「大类」（`groupUnits[i].section`，18 个，**类别内**唯一），
  数据里本来就有，不需要改 `js/codex.js`、也不需要新数据。大类名只在**类别内**唯一是
  数据层的约定，跨类别不重名只是当前数据碰巧如此 —— 平铺就是拿巧合当契约（实测
  「回忆之旅」在障碍物代码里出现两次：`主线与回忆` 29 条、`裂缝合集` 23 条）。更实际的
  理由在名字本身：「图鉴中的植物」「主线僵尸」不告诉你它属于哪一类，条数也只有配上
  类别才有意义。所以侧栏是**三级**：类别 → 大类名 → 次级项（5 类别 / 18 大类 / 80 次级项）。
  ⚠ 旧图鉴站的侧栏其实只有**两级**（章 → 次级项），大类名是遍历时顺手插的一个标签。
  这儿把那个标签也算一级、并且让五个类别的目录同时存在于 DOM 里，是**这一版自己加的** ——
  别照着旧站"改回去"。
  ⚠ 三级里**每一级都是入口**（2026-09-22 起）：类别行 → 开浮层、读到那一类；大类名 →
  同上并滚到那一段；次级项 → 同上并滚到那一组。所以大类名是 `.codex-sec-btn`
  一个**按钮**，而且**不能**带上 `.codex-entry` 那个类 —— 带了侧栏入口数就被算重
  （自检里有一条专门钉这个）。`buildTree()` 里那两行注释别删。
  ⚠ 用户点名把用户可见的「章节」改成了「类别」（「章节」跟关卡那一套术语容易混），
  但中间那一级**仍然叫「大类」**。所以现在「类别 / 大类」只差一个字，读的时候容易看串 ——
  这是有意的取舍，如实记在这儿。
- 浏览态画的是**一整个类别**（最坏 1048 条，僵尸代码），而且**打开即画完，不分页** ——
  旧图鉴站本来就是一次性画完整章 2333 条，所以这是回到旧站的形状。中间那版加过
  「还有 N 条，显示更多」，用户报"点了像没反应"（jsdom 里复现不出来，机制本身是好的，
  所以大概率是视觉问题：补上来的行落在视野外，按钮自己往下挪）。去掉分页既回到旧站的
  样子，也把那处没查清的毛病整个绕开。搜索态由 `js/search.js` 自己截到 400 条，那条提示条
  保留。
  粒度从「一个大类」提到「一整个类别」是用户要的：点「植物代码」底下任何一项，出来的都该
  是完整的植物代码 430 条，而不是只有「图鉴中的植物」那 382 条。
- 侧栏的「当前类别」和浮层的「当前类别」**是同一个变量**：`ui.chapterId`。2026-09-22
  之前这里有两个 —— `viewCh`（目录翻到哪一类）和 `ui.chapterId`（浮层在读哪一类），
  只有**单向**同步（开浮层把 `viewCh` 拉过去，点类别行**只**改 `viewCh`）。用户点名要
  反过来：「侧边栏点击上面的大类浮窗就应该跟着切换，而不是等到选择了次级分类」——
  于是 `viewCh` 整个删掉、两级合一，三级目录里**点哪一级都开浮层**（类别行不带 `unit`、
  大类名带本大类的扁平起点、次级项带组内下标，三条路殊途同归到 `openOverlay`）。
  当初分两个变量的两个理由是：`rerender()` 有跟换类别无关的调用方（换格式、打字、开
  浮层），让"只翻目录"去写 `ui.chapterId` 会"画着 A 类、状态记着 B 类"；以及切类别顺手
  换浮层会把"只想翻翻目录"的人的阅读位置扔掉。现在这两条都不成立了 —— 前者是因为
  翻转之后"点类别行"本身就等同于"开浮层"，写 `chapterId` 的那一行**紧接着就
  `rerender()`**，不存在中间态；后者是用户明确不要的（他要的就是点一下就换）。
  ⚠ 副作用：窄屏下点类别行**现在也会收抽屉**（它一样走 `onOpen`），以前那条"翻目录
  不收抽屉"的理由随目录联动一起没了。见手工清单第 16 条。
- **`at` 是承重的一个整数**：它是次级项在**类别内**的扁平下标，同时是 `groupEls` /
  `idxBtns` 的下标、侧栏那行的 `dataset.idx`。四个是同一个数，所以滚动联动那条规则就是
  一句 `e.idx === at`，不用换算。算扁平下标**不能用外层累加变量**（`var flat = 0; flat++`
  配 `forEach` 闭包，所有监听器会共享末值 —— 点哪个次级项都跳到最后一组），得用
  「本大类起点 + 组内下标」。
- `ui.section` 和 `pairSection()` 随这一版删掉了：浮层不再属于任何一个大类，把"类别和大类
  配成一对、配不上就退回第一类"那套整个失去意义。删掉的那条 `renderIdx` 守卫
  （`units.length < 2` 就不画目录）也一样 —— 整个类别的次级项最少 7 个，它是个**变异打不红**
  的分支。
- 搜索**只在浮层当前这一类里**（用户 2026-09-22 原话：「图鉴栏浮窗里搜索仅允许在当前
  类别里搜寻代码，例如在查看植物页面时浮窗顶部的搜索只能搜索到植物代码」，同时点名
  「不需要侧边栏的搜索入口，不需要筛选范围按钮」—— 三样一起改了，`scope` / 那个按钮 /
  那个小浮层 / 侧栏顶上那个入口全删）。清空搜索框回到浏览态，打开的那一类**原样还在**。
  它住在浮层里，所以侧栏那一页**一个输入框都没有**：输入框一进侧栏，那个 310px 的缝里
  就再塞不下别的东西了 —— 这条从第一版起就没变，只是"搜索"现在也不再从侧栏进来了。
  实现上作用域在**调用方**（`codex-panel.js` 的 `searchScope()` 只返回当前那一章，
  `js/search.js` 一个字没改，它本来就只负责"在给我的这几章里打分"）。
  ⚠ 空结果那行提示写着**当前类别名**（「「植物代码」里没有匹配的条目」）—— 用户看到
  0 条时第一反应是"是不是坏了"，这一句是唯一的解释；想搜别的类，回侧栏点那一类。

**次级目录**：一个元素、一份 JS，**宽屏收掉、窄屏是顶上一行横滑的 chip**
（仿旧站同一断点下的 `.groupbar`）。它列的是**整个类别底下**的全部次级项（7～31 组），
点一下滚到那一段、滚动时高亮跟着走。

**为什么宽屏收掉**：浮层现在画的是整个类别，跟侧栏那三级目录**完全重复**了 —— 用户
原话是「宽屏状态下浮窗里不需要次级目录显示了，因为和侧边栏作用一样」。窄屏就得留着：
那时候侧栏是一个关着的抽屉（点开次级项就自己收起来，`ctxRef.onOpen` 那条），浮层是
唯一还在的界面 —— 撤了它，窄屏用户在 1048 条里就没有任何目录可用。

**收掉是 CSS 收的，DOM 照建**（`display: none` 写在基础规则里，窄屏断点那条
`display: flex` 排在文件更后面，天然赢）。这不是偷懒，是文件里那条规矩：**JS 只管行为，
宽度只管样式**。跟着走有三个好处：不用问 `matchMedia`（问了就是"JS 的断点和样式表的断点是
两份真源"，旧站就栽在这）；**jsdom 不求值 media query**，照建的话 `check-boot.js` 第 10b 节
那一整批 chip 行为断言（居中、两侧渐隐、滚轮横滚、不溢出时不抢滚轮）**原样全部继续有效**，
改成"宽屏不建"那批断言会集体变成测不到的死代码；而且窄屏那条 chip 要列的正好是同一份数据。
⚠ 宽屏下那几十个索引按钮是**看得见地不存在**的，所以 `.codex-midx` 那条"宽屏是
`display: none`"只有静态断言抓得住（`check-editor.js`，对应变异 `N17`）。

三处讲究（前两处两种形态通用）：

- **跳转是瞬时的**（`out.scrollTop = headerEl.offsetTop - out.offsetTop`），不用 `smooth`：
  列表是整块重画的，条子自己在那儿慢慢滑显得很脱节。
- ⚠ `.codex-out` 上有 **`position: relative`，这是承重的**：`offsetTop` 相对最近的
  **定位**祖先算，少了它 `offsetTop` 就相对 `body`，跳的位置整个是错的。旧站 `.content`
  上也有这条。jsdom 不做排版（`offsetTop` 恒 0），所以这条**只能静态验**
  （`check-editor.js` 里那条断言）。
- **不加 `requestAnimationFrame` 节流**，这是跟旧站唯一一处不同：旧站要节流是因为它扫的是
  上千条 `.item`，这里扫的是**分组标题，最多 31 个**。不加还有个实在好处 ——
  `check-boot.js` 是**全同步**套件，rAF 回调根本跑不到，加了节流那条断言就只能靠打桩
  才测得动，而测出来的也只是桩本身。

**窄屏那一版（横滑的 chip 条）**。原先这儿写的是 `.codex-midx { display: none }`，
理由是「浮层只有一屏宽，168px 给目录不如给条目」。理由成立、结论不成立 —— 整条藏掉之后
1048 条的「僵尸代码」在窄屏上只能硬滚，而目录恰恰是那时候最需要的东西。用户报的就是这句
（「图鉴浮框的分类目录窄屏不可见」）。横条只吃掉一条高度（约 43px），不再跟条目抢宽度。
三件事都是从旧站搬的，只有一处改了写法：

- **高亮滑进视野**：点/滚到后面的分组时，条子要把当前那一格滑进来（不滑的话高亮落在
  可视区外面，等于没高亮）。旧站用的是 `scrollTo({behavior:'smooth'})` —— **照搬会让
  整个 check-boot 当场炸**：jsdom 里 `Element.scrollTo` 压根不存在（`undefined`），
  而它是全同步套件，没有"未实现"这种软着陆。现在用 `scrollLeft` 赋值（jsdom 读写都正常），
  反正浮层里的跳转本来就定的瞬时。
- **两侧渐隐**：条子藏了滚动条（`scrollbar-width: none`），"右边还有分组"就只剩这一个
  提示。用 `mask-image` 而不是叠一层渐变 —— 条子自己就是滚动容器，叠层会跟着内容滚走。
  1px 余量留给亚像素取整，少了它滚到底时右边那道一直不消。
- **滚轮横滚**：鼠标在窄屏下既没有滚动条可拖、也没有横向滚的习惯，不接管这一条就是个
  死区。只在**真的滚动了**的时候 `preventDefault`，没溢出就原样放给列表。
- ⚠ 窄屏那条还多一句 `.codex-out { min-height: 0 }`：`flex-direction` 换成 column 之后，
  少了它列表的自动最小尺寸就是内容高度，1048 行把浮层整个撑破、`overflow-y: auto` 形同
  虚设。**jsdom 不做排版，这条只有静态断言 + 人眼**（`M36`）。

那三件事在宽屏下全是**空转** —— 整列 `display: none`，`scrollLeft` 恒 0，也没有左右边界。
空转而不是加一句"现在是不是窄屏"：那得问 `matchMedia`，而它跟样式表里那个断点是**两份
真源**，迟早对不上（旧站就是让两边各管各的：JS 只管行为，宽度只管样式）。

**搜索范围（筛选）· 整套已删**（2026-09-22，用户原话：「不需要筛选范围按钮」）。
留一段记录免得有人再"顺手加回来"：它当年是「☑ 范围」按钮 + 一个勾选小浮层 + 三态
（`null` 全选 / 数组 / `[]`）+ `localStorage` 持久化，靠**把筛过的章数组喂给 `search()`**
实现（不是事后过滤 `hits` —— 那会让 `res.total` / `res.truncated` 说谎）。删掉的理由不是
实现难看，是**它跟"搜索的作用域就是当前这一类"不能共存**：留着那个按钮，用户就会以为
自己能改范围，而实际上改不动（面板只喂当前这一章）。所以现在是**一个作用域、没有开关**，
配套的还有两条一起没了的：空结果里那个「改为搜索全部代码」出口（它存在的理由随范围
一起没了）、以及侧栏顶上那个「搜索全部代码」入口。
`check-boot` 第 13 节是**反向**用的 —— 它钉的是这套界面**没有偷偷长回来**
（`.codex-fbtn` / `.codex-fpop` / `.codex-entry-all` 的 `querySelectorAll` 必须是 0 个，
`state().scope` 必须是 `undefined`），
变异体 `N1e` / `N1f` / `M30` 就是往这三条上撞的。

**排列密度三档**（宽松 / 标准 / 紧凑）改字号、行距、每列最小宽度，走 CSS token 换挡
（`--cx-fs` / `--cx-py` / `--cx-col` / `--cx-gap`），布局规则一行不碰。两处跟旧站不同：
状态挂在 **`.codex-modal` 的 `data-density`** 上而不是 `<html>`（旧站整站只有图鉴；
这里 `:root` 上的 `data-density` 会漏进编辑器和另外两个页签）；**标准档 = 把属性删掉**
（跟旧站 `applyDensity()` 一样，回落到基准值），所以样式表里只有宽松/紧凑两条覆盖。
⚠ 已知退化点：紧凑档列宽 190px 时 `.codex-name` 会被先挤没，只剩代码。
- 不做防抖 —— 几千次字符串比较不需要；真正的首次开销是拼音索引的懒建，浏览态用不到它，
  所以**保持懒建**，别为了"预热"挪到 boot。

**手势：点击复制、长按插入。** 这两条都是用户定的。图鉴是常驻浏览面，用户在那儿主要是
**查**，"点一下"就该是查代码时最顺手的那个动作（复制）；插入是少数，所以换成需要刻意做
的长按。判定全在 `row()` 里：`pointerdown` 起一个 500ms 定时器，`pointerup` /
`pointercancel` / `pointerleave` 取消，`pointermove` 位移超过 10px 也取消（触屏滚列表时
浏览器要越过 pan 阈值才发 `pointercancel`，阈值内的小幅慢拖不发，只能自己补一刀）。
只有**一个**"当前按压"存在模块作用域里，不是每行一个闭包 —— 否则触屏长按弹原生菜单后
浏览器可能根本不补发 `click`，那个残留的 `held` 布尔会让这一行以后再也点不动。

三条已知代价，都是有意的：

- **长按不好发现。** 没加按钮、没加提示，这是用户选的（"就长按，不加按钮"）。
- **条目里的代码不能手动选中了**（`.codex-item { user-select: none }`）。旧图鉴站给
  `.it-code` 留了 `user-select: text`，注释写着"复制失败时还能手动选"；长按已经是插入手势，
  再让行内可选就会打架。复制真失败时 toast 说的是「请手动选中代码」，而从**编辑器里**
  选仍然可以。
- **Esc 归浮层。** 这是本仓库第一处 Esc 处理，走**捕获阶段 + `stopPropagation`** ——
  浮层开着时 Esc 就是关浮层，CM6 收不到这一个 keydown。不能用 `if (e.defaultPrevented) return;`
  那套：CM 的 `defaultKeymap` 绑了 Esc（`simplifySelection`，选区非空时才 `preventDefault`），
  加了那句之后"浮层开着且编辑器里有选区"就永远关不掉。

复制格式三档（纯代码 / 带引号 / RTID）跟原图鉴站一致，**共用同一个 localStorage 键**
（`zeditor.copyFormat`），所以两边设置是通的。三档的值和默认档（`quoted`）**一个字都没改**，
只是控件从浮层搬到了**侧栏图鉴页顶上** —— 它是全局设置，却要开浮层才能改，说不通。
RTID 表名来自数据里的 `rtid` 字段，
不是 UI 里写死的映射表 —— 维持「新增类别不用改 UI」这条约定。拼不出 RTID 时回退成
「带引号」而不是裸代码，**并且 toast 里会交代一句**「（本类别无 RTID 表，回退带引号）」
—— 用户选了 RTID 却拿到带引号的串，不说明会以为是 bug。

插入和复制都**不抢焦点**：复制只是写剪贴板；插入走 `main.js` 的 `insertSnippets`，
插完焦点仍在浮层里，可以接着插下一条。插入位置照旧正确 —— DOM 焦点跟 CM state 里的
selection 是两回事。

写剪贴板走 `navigator.clipboard`（要求安全上下文，而 `file://` / `localhost` / https 都算），
兜底是老 API `document.execCommand('copy')` —— 它要在文档里真插一个 textarea 并选中，
所以**必须包在 try/catch 里**（jsdom 里 `document.execCommand` 根本不存在，裸调直接 TypeError）。
`writeClipboard` 返回的 promise **永不 reject**：jsdom realm 里一个未处理的 rejection
会让 node 以退出码 1 直接终止，扫雷要点几十次条目，第一次就能把整个套件打死。

**为什么图鉴数据是 `.js` 而不是 `.json`**：`file://` 下 `fetch` 会被 CORS 拦掉，而 `<script>`
不会。用 `.js` + `Codex.add({...})` 还顺带允许写注释和尾逗号，手工维护友好得多。
`data/modules.js` / `data/templates.js` 同理（两者是生成物，分别由
`tools/gen-modules.mjs` / `tools/gen-templates.mjs` 从 Z-Editor 源码抽）。
`data/module-docs.js` 也走 `.js`，但它是**给人填的**：`tools/gen-module-docs.mjs` 只打底
（键名列全、中文空着），之后手工维护，重跑不覆盖已经写好的中文。
